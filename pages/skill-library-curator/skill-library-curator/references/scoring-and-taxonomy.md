# 类型判定、评分与分类

第 2 步用。**同一次运行内，所有批次必须逐字共用本文的锚点与枚举**，否则口径漂移，分数无法横向比较。

## 一、先定类型，再打分

三态取一，这是硬路由。判为参考素材或存疑的**不打分**，直接跳过第二节。

### 量化信号

统计这几类词在正文中的出现次数：

| 词类 | 例词 |
| --- | --- |
| 第二人称指令 | 你是、你需要、你应该、请 |
| 流程 | 步骤、第一步、流程、依次、然后 |
| 输出约定 | 输出、交付、格式、模板、返回 |

一份真 skill 这些词是密集出现的。若三类合计接近零、通篇为陈述或说明文体，基本可判参考素材。

### 判定表

| 特征 | 倾向 |
| --- | --- |
| 含 `SKILL.md`，或 frontmatter 里有 name/description | skill |
| 有角色设定（「你是一位…」） | skill |
| 有面向执行者的步骤，且规定了输出格式或交付物 | skill |
| 指令密度接近零，通篇陈述 | 参考素材 |
| 正文写着「Skill 名称: xxx」「作者: xxx」这类第三人称元描述 | 参考素材（这是介绍页，不是 skill） |
| 标题或首屏含：作业、展示、练习、分享、介绍、assignment | 参考素材 |
| 是填空模板、图解、汇报材料、观察报告、对话记录、设计稿 | 参考素材 |

**格式不能单独定性。** PDF 和 pptx 天然偏向展示物料，可以加重反面权重，但确实存在把可用 skill 导成 PDF 的情况，必须看内容。

正反面特征同时命中且强度相当时，判**存疑**，列给用户，不要自己拍板。

### 词频判不出来的两种情况

实测中词频判据在这两类上会判错，必须补一眼正文开头：

**一、某个 skill 的输出产物。** 一份填好的行动卡、生成的诊断报告、导出的个人上下文。它开头往往带着「把本文件上传给你的智能体」这类使用说明，指令密度很高，词频看着像 skill。识别信号：**内容是某个具体的人的具体问题**，含生成时间、使用模型、个人背景这类实例化字段。它是产物不是生产者，不可复用，判参考素材。

**二、纯理念介绍。** 通篇讲「为什么做这个技能」「核心方法是什么」，流程词和输出词都不少，但**第二人称指令为零**——没有一句是对执行者说的。识别信号：作者以创作者口吻自述（「我踩过的坑」「技能作者自己就是…」）。判参考素材。

### 说明文档要再分一层

第三人称的「说明文档」有两种，别一刀切：

| 结构 | 判定 |
| --- | --- |
| 作业模板结构：「1. Skill 名称 / 2. 我想解决的问题 / 3. …」 | 参考素材。这是交给人评审的作业 |
| 技能文档结构：「概述 / 适用场景 / 核心框架 / 执行流程」 | skill，可用标「部分」。内容是完整可执行的方法论，只是导出成了 PDF 需转格式 |

判断的落点是：**这份东西是给人看的，还是拿去就能让 AI 照着做的。**

## 二、五维评分

只对判为 skill 的条目打分。总分 100，权重固定：

| 维度 | 权重 | 看什么 |
| --- | --- | --- |
| 完整度 | 30 | 角色、流程、规则、输出规范是否齐全；边界条件是否交代 |
| 结构化 | 25 | 是否符合 Agent Skill 规范，能否直接喂给 AI 执行；有无判据表 |
| 实用度 | 25 | 问题是否高频、受众是否广；产出是否可直接用 |
| 原创性 | 10 | 是否有作者自己的方法论沉淀，而非通用常识的重述 |
| 交付物 | 10 | 参考文档、脚本、模板、示例是否配套 |

### 各维度锚点

打分时对照锚点，不要凭印象给中间值。

**完整度**：全流程闭环且交代了失败与边界 = 26-30；主流程完整但边界模糊 = 18-25；只有片段或大纲 = 10-17；仅有概念描述 = 0-9。

**结构化**：有明确步骤与判据表，可直接执行 = 21-25；有步骤但需要自行补充判断 = 14-20；只有原则性描述 = 7-13；无结构 = 0-6。

**实用度**：问题真实高频且产出可直接用 = 21-25；场景较窄或产出需二次加工 = 14-20；场景边缘 = 7-13；难以想象使用场合 = 0-6。

**原创性**：有独到方法论或框架 = 8-10；在通用做法上有实质改良 = 5-7；通用常识重述 = 2-4；纯搬运 = 0-1。

**交付物**：产出形态明确且给了示例 = 8-10；说明了产出但无示例 = 5-7；产出形态模糊 = 2-4；无产出概念 = 0-1。

### 等级

| 等级 | 分数 | 含义 |
| --- | --- | --- |
| S | 90-100 | 直接可用且体系完整 |
| A | 80-89 | 质量好，小改即用 |
| B | 70-79 | 框架可用，细节需补 |
| C | 55-69 | 有参考价值，需重写 |
| D | 0-54 | 仅存档 |

### 评分必须带证据

每条至少写一句依据，并指向具体特征，例如「有七步流程与三处判据表，但未交代输入缺失时怎么办」。**禁止只有形容词**——「质量不错」「比较完整」这类无法复核，用户也没法判断该不该信。

## 三、分类枚举

默认九类，一律用两位数字前缀。用户可在确认环节增删，**一旦确定就冻结并写入账本**，本次运行内不再变动。

| 前缀 | 分类 | 收什么 |
| --- | --- | --- |
| 01 | 职业发展 | 求职、简历、面试、晋升、职业规划、汇报 |
| 02 | 个人成长 | 时间管理、习惯、认知、情绪、学习方法 |
| 03 | 创业与商业 | 商业模式、增长、销售、副业、财务 |
| 04 | 内容创作 | 写作、短视频、账号运营、选题 |
| 05 | 英语学习 | 听说读写、考试、词汇 |
| 06 | 健康养生 | 饮食、运动、睡眠、中医调理 |
| 07 | 家庭教育 | 亲子沟通、学习陪伴、儿童发展 |
| 08 | 行业专业 | 特定行业的专业工具与流程 |
| 09 | AI与方法论 | 提示词、AI 工具、通用方法论框架 |
| 98 | 参考素材 | 非 skill 的知识、样例、设计稿，用 `M-` 编号 |
| 99 | 重复版本归档 | 去重后保留的旧版本或重复副本 |

归类拿不准时按**使用者身份**判断：这个 skill 是给谁用的，就归到那个人群最相关的类。同一条目只进一个分类，不做多重归属。

## 四、两处锁定

**权重锁进账本。** 权重可按用途调整（自用调高实用度，分享调高结构化与交付物），但调整会让新旧条目分数不可比，而报告是按分数排序的，存量条目位置会莫名跳动。规则：权重写入账本，增量时禁止变更；确需变更则触发全量重评。

**模型标识写进账本。** 不同模型的打分尺度不同。增量时若检测到模型与账本记录的不一致，提示用户「分数可能与存量不可比，建议全量重评或接受偏差」，由用户决定。

## 五、分批规则

按上下文预算切分，不给固定条数。但同一次运行内：

- 所有批次拿到的评分锚点、分类枚举、类型判定表必须**逐字相同**
- 每批处理完立刻把结果落盘成 JSON，不要攒在上下文里
- 批次编号连续，便于中断后核对哪些已完成

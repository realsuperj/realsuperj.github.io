# 分析报告模板

第 6 步用。报告默认命名 `Skill分析报告.md`，放 `{target}` 根下。**不要叫 README.md。**

## 写给谁看

预设读者不是程序员。全文避免这些词：frontmatter、references、YAML、渐进式披露、schema。确实要提时换成大白话：「文件开头的配置区」「拆出去的参考文档」。

「形态」「可用」这类列的取值也用大白话，不用英文枚举。

## 可选的开头配置区

若 `{target}` 在笔记软件的库里，可以加一段 frontmatter 便于索引。**是否生成由用户决定**，默认加，用户说不要就去掉。

```yaml
---
tags:
  - AI/skills/收集清单
---
```

## 五块结构

### 第一块：一句话总览

```markdown
# Skill 收集清单（已分类评分）

共收录 **N** 个条目：主清单 **N** 个可用 skill，参考素材 **N** 个，重复版本归档 **N** 个。
```

增量运行时在这句下面加一行变更摘要：本次新增 N 条、更新 N 条、移除 N 条。

### 第二块：怎么读这份清单

必须解释清楚评分怎么来、等级怎么分、每列什么意思。照抄以下措辞，把权重数字换成账本里实际用的：

```markdown
## 怎么读这份清单

**评分**：满分 100，由五项加权而成 —— 完整度 30%（角色/流程/规则/输出规范是否齐全）、
结构化 25%（是否符合 Agent Skill 规范，能否直接喂给 AI）、实用度 25%（问题是否高频、
受众是否广）、原创性 10%（有无独到方法论）、交付物 10%（参考文档/脚本/模板/示例是否配套）。

**等级**：S≥90 直接可用且体系完整 ｜ A 80-89 质量好，小改即用 ｜ B 70-79 框架可用，
细节需补 ｜ C 55-69 有参考价值，需重写 ｜ D<55 仅存档。

**形态**：`解压包` 已解压的完整 skill 包（原压缩包以 `_原始压缩包_` 前缀保留在同目录）；
`文件夹` 原本就是多文件目录，内部压缩包已额外解压出 `_解压` 副本；`单文件` 单个 md/pdf/docx。

**可用**：`是` 可直接安装使用；`部分` 需转格式或补依赖文件。
```

注意：**主清单里不应出现「可用=否」**。判定为「只是说明文档、要重写才能跑」的条目属于参考素材，应该在第四块，不该占用 skill 编号。

### 第三块：目录与分类小节

目录列出每个分类、条目数、一句话说明，锚点指向下方小节。

每个分类小节是一张表：

```markdown
## 01-职业发展

> 求职、简历、面试、晋升、职业战略、职场沟通、团队管理

| 编号 | 名称 | 分 | 级 | 说明 | 形态 | 可用 | 原始文件名 |
| --- | --- | --: | :-: | --- | :-: | :-: | --- |
```

列的规则：

- **编号**：`分类前缀-序号`，与磁盘上的文件名前缀严格一致，这是双向溯源的锚
- **名称**：加粗，用能看懂的中文名，不用原始英文 slug
- **说明**：一句话讲清它替用户做什么，不超过 40 字，不堆形容词
- **原始文件名**：用反引号包住，这是账本丢失时反向重建的依据，**不能省**

**排序按分数从高到低，编号只作 ID 列。** 增量整理后编号不再等于分数序位，这是有意为之——编号是身份标识，重排会让用户之前记住的编号全部作废。

### 第四块：参考素材与重复归档

```markdown
## 98-参考素材

> 有价值但不是 skill 的知识库、样例与设计稿

| 编号 | 名称 | 说明 | 原始文件名 |
```

参考素材**不列分数和等级**。给写给人看的材料打分没有意义，还会让读者误以为它们是低质 skill。说明里点出它是什么类型：知识库、作业展示、设计稿、对话记录、行业报告。

重复归档区列出：编号、名称、与主清单哪一条重复、原始文件名。

### 第五块：怎么用这些 skill

放在末尾，大白话，一段话讲完：

```markdown
## 怎么用这些 skill

想用哪个，把它的编号或名字告诉你的 AI，让它装到你当前所用客户端对应的位置。
各家客户端的目录约定不一样，让 AI 按你的实际环境判断即可。

建议按需要装单个，不要一次全装 —— 每个装上的 skill 都会占用 AI 的上下文，
装太多反而容易误触发。
```

**不要列举任何具体客户端名称，不要写死任何路径。** 各家约定不同且会变。

## 三条硬约束

- 报告里每一行的目标路径，必须真实存在于磁盘。生成后逐条断言，不过不许收工
- 编号在各分类内唯一且与文件名前缀一致
- 表格排序（按分数）与编号分配（按入库顺序）是两套逻辑，不要试图让它们一致

## 增量运行时的更新方式

报告整体由账本重新渲染，不做局部修补——局部改容易漏。渲染前把旧报告备份为 `Skill分析报告-上一版.md`。
